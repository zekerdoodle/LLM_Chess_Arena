# Things That Went Wrong (and how we fixed them)

This document tracked gaps during early development. As of 2025‑09‑08, all items below are addressed and verified by code and tests.

— Room Management
- Status: Fixed
- What changed:
  - Auto‑scroll on room switch, on optimistic user sends, and on assistant streaming/appends.
  - Startup room selection now chooses the most‑recently active room (by last message timestamp), not the first room ever created.
- Evidence:
  - Auto‑scroll: `web/src/ui.ts`, `web/src/history.ts`, `web/src/hooks/useComposer.ts`.
  - Most‑recent room selection: `web/src/events.ts` (uses `utils/roomSelect.pickMostRecentRoom`).
  - Tests: `web/src/__tests__/auto_scroll_on_send.spec.tsx`, `auto_scroll_on_streaming.spec.tsx`, `autoscroll_on_room_click.spec.tsx`, `auto_scroll_on_assistant_append.spec.tsx`.

— Tasks + Notifications
- Status: Fixed
- What changed:
  - Read‑only Tasks panel wired to live SSE: `web/src/components/TasksModal.tsx`; openers in header/sidebar.
  - Scheduler queue delivers notifications/tasks to a NEW room by default, but honors an explicit `room_id` when provided.
  - Silent tasks suppress the user trigger message, yet still persist assistant output (per spec).
- Evidence:
  - API: `server/routers/tasks.py` (CRUD + SSE stream).
  - Delivery: `utils/queue_processor.py` (see `_send_notification_message` and `_send_task_message`).
  - Tests: `tests/test_push_notifications.py`, `tests/test_silent_task_persistence.py`.

— UI (message distinction and orb)
- Status: Fixed
- What changed:
  - User messages render in a right‑aligned bubble with max‑width 75%; Theo remains full‑width.
  - Orb refactor: status chip (“Thinking/Using tools/Replying”), tool icons, and animation hooks.
- Evidence:
  - Bubble: `web/src/features/messages/MessageItem.tsx`, styles injected in `web/src/main.tsx`.
  - Orb: `web/src/components/HeaderBar.tsx`, `web/src/orb.ts`, `web/src/orb/reasoning.ts`.
  - Tests: `web/src/__tests__/user_message_bubble.spec.tsx`, `orb_status_label.spec.tsx`, `orb_animation.spec.tsx`.

— Backend: Long‑term Memory injection
- Status: Fixed
- What changed:
  - Prompt now includes a Memory Bank built via `Layer3MemoryManager` with relevance‑first blending and deduping of verbatim memories against recent chat.
  - Tools docstrings are included in the prompt text (in addition to native tool schemas).
- Evidence:
  - Prompt assembly: `utils/prompt_printer.py` (`build_prompt`, `build_memory_bank`).
  - L3 manager: `layer3_longterm/memory_manager.py`.
  - Tests: `tests/test_core_memory_manager.py`, `tests/test_human_memory_injection_order.py`, `tests/test_prompt_printer_fastpath_fallback.py`.

— Backend: Agency on startup
- Status: Fixed
- What changed:
  - System instructions explicitly document the Task‑Chaining technique.
  - A seed meta‑task (“Meta: How do I agent?”) is created on startup if missing.
- Evidence:
  - System guidance: `layer2_shortterm/prompt_builder.py` (Task‑Chaining section appended to system prompt).
  - Seeder: `utils/agency.ensure_meta_task_seed()` invoked in `server/app.py` startup.
  - Seed data: `vault/scheduled_tasks.json` (created at runtime if not present).

Notes on prompt order and tools docstrings
- The prompt order now follows the spec: System → Available Tools (docstrings + concise guidance) → Memory Bank → (Todo) → Chat History.
- Docstrings are generated by `utils/tool_schemas.generate_tools_docstrings()` and included by `utils/prompt_printer.build_prompt()`.

Cleanup
- Tests that previously polluted `sys.modules` were updated to use `monkeypatch.setitem`, preventing cross‑test leakage.
- Static uploads route now serves dynamically from the current vault root to support test overrides of `THEO_VAULT_ROOT`.
- No duplicate or junk code detected; legacy paths remain only for migrations and are guarded with clear comments.

If you spot regressions, re‑open this document with details and we’ll log a follow‑up task.
